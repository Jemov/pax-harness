# Программы сущностей

[English](entity-programs.en.md)

Помощник получает формат через `creation.program_schema`, проверяет исходный текст инструментом `creation.validate_program` и предлагает объект с полем `program`. Игрок подтверждает модель и логику вместе. Для изменения программы существующего объекта используется проект `behavior` с `object_id`; если его `id` совпадает с `object_id`, программа заменяется без пересоздания модели. По умолчанию сохраняются прежние значения переменных.

Это ограниченный интерпретируемый JSON, без выполнения GDScript. Программа может составлять новые правила из доступных операций, но не добавляет отсутствующие возможности движка.

## Пример счётчика

```json
{
  "version": 1,
  "state": {"count": 0},
  "events": [{"name": "pulse", "type": "tick", "seconds": 1}],
  "handlers": {
    "pulse": [{"set": "state.count", "value": {"op": "+", "args": [{"get": "state.count"}, 1]}}]
  },
  "ui": {"fields": [{"label": {"ru": "Импульсы", "en": "Pulses"}, "path": "state.count"}]}
}
```

`state` сохраняется с партией. `event` содержит данные события, `self` — ID объекта и тело. Значения `let` и результаты `call` с `store` доступны по имени и через `local.имя`. Временные переменные действуют только внутри обработчика.

## События, выражения и действия

- `tick` — таймер в секундах сцены, в том числе при остановленном календаре; `day_change` — изменение игрового дня.
- `interaction` — нажатие кнопки из `ui.buttons`, которая указывает имя события через `event`.
- `plane_cross` и `sphere_enter` — пересечение плоскости или вход в область реальным кораблём. Сейчас адаптер `dyson` требует включённую «Сферу Дайсона». Центр, нормаль и радиус задаются относительно объекта в километрах. Проверки размера, запаса энергии и другие условия пишет агент.
- Инструкции: `let`, `set`, `if`/`then`/`else`, `for`/`in`/`do`, `while`/`do`, `call`, `return`. В `set` разрешены только пути `state.*`; необязательный `key` задаёт вычисляемый ключ словаря.
- Выражения: `get` с необязательным `default`, `literal`, арифметика, сравнения, логика, `min`, `max`, `clamp`, `len`, `concat`, `at`, `vadd`, `vscale`, `dot`, `distance`. Читающие операции также можно вызывать внутри выражений.

Полные обязательные поля и примеры возвращает `creation.program_schema`. Он является справочником для модели, поэтому ей не нужно угадывать формат по этому описанию.

## Общие операции над миром

| Операция | Результат |
| --- | --- |
| `body.read` | Настоящее население, наличие колонии и климат открытого тела |
| `body.set` | Изменение климатических параметров подтверждённого искусственного тела или оболочки |
| `actor.read`, `actors.list` | Данные настоящих кораблей игрока, включая прочность, груз и положение |
| `actor.spawn` | Выпуск настоящего корабля «Сферы Дайсона»; стоимость, очередь и сроки задаёт программа |
| `actor.move` | Перенос того же корабля в заданную точку у открытого тела; груз, войска, прочность и владелец сохраняются, предыдущие приказы отменяются |
| `actor.set` | Изменение прочности или щита в пределах штатного максимума |
| `object.read` | Положение, оси и определение подтверждённого объекта |
| `object.move` | Перемещение созданного объекта с сохранением в партии |
| `object.damage` | Удаление ограниченной области разрушаемого воксельного объекта |
| `resource.add` | Изменение запаса существующего ресурса настоящей колонии |
| `resource.read` | Чтение действительных запасов для проверки стоимости или питания |
| `ui.message` | Сообщение в журнале программы |

`actor.move.position_km` задаётся относительно центра тела, в мировых осях. Внутри удерживаемое положение и направление сохраняются в системе тела, чтобы при загрузке сцены корабль оставался в том же месте относительно планеты. Для смещения в системе выходного объекта прочитайте `object.read`, умножьте его ось на нужное расстояние и сложите с его положением. Движок не предполагает, что объект — врата: датчик, условия и место назначения описывает программа.

`ship_flight` отдельно задаёт маршрут настоящего корабля по 3D-точкам относительно объекта. Маршрут лишь двигает корабль; реакция при входе в область выполняется программой. Камеру к самому объекту переносит `creation.focus` или кнопка карточки.

## Состояние и ошибки

В карточке доступны показатели, кнопки и выключатель программы. `creation.program_status` возвращает фактическое состояние, последние выполненные операции и конкретную ошибку с путём в исходном тексте. Ошибки также поступают в контекст создавшего программу чата через `workspace.program_feedback`.

`creation.actors` позволяет агенту отдельно прочитать настоящие корабли адаптера: ID, положение относительно выбранного открытого тела, груз и прочность. Это не список штатных транспортов с расписанным прибытием (`ships.read`). Чтение не требует создания программы или изменения мира.

При ошибке программа останавливается. Уже выполненные действия не откатываются. Исправление предлагается отдельным подтверждаемым проектом; повторять успешные изменения мира для исправления ошибки не требуется.

На программу разрешены 8 событий, по 12 показателей и кнопок, до 64 КиБ исходного текста и состояния. Обработчик ограничен 4096 инструкциями; цикл по массиву — 64 элементами. Очередь событий общая, до 256 записей, по 16 обработчиков за кадр. Доступа к файлам, сети и произвольным методам движка из программы нет.


Старый формат `ui.workspace.columns` задаёт одну или две колонки из секций `choices`, `fields`, `list`, `progress` и `actions`. Точные форматы и ограничения доступны через `creation.program_schema.workspace`. Вариант выбора содержит подписи на русском и английском и объект данных `value`. Действие с `inputs:["design"]` вызывает обработчик взаимодействия с выбранными данными в `event.input.design`. Очередь, сроки, проверку запасов и изменения мира реализует сама программа. Инструмент `creation.open_controls` открывает подтверждённую панель, не выполняя её действия.


## Составляемый интерфейс

Для свободной раскладки используйте `ui.workspace.layout`: дерево контейнеров и элементов из `creation.program_schema.workspace.tree`. Старые `columns` сохраняются для совместимости. Не смешивайте `layout` и `columns`.

Контейнеры `row`, `column`, `grid`, `tabs`, `panel`, `scroll` вкладываются друг в друга. Узлы `input` поддерживают `text`, `textarea`, `number`, `slider`, `toggle`, `select`. `button.inputs` перечисляет ID полей; обработчик получает их типизированные значения в `event.input`. Поля держат локальный черновик и не меняют мир. Для применения пишите обработчик программы. Узлы `text`, `value`, `progress`, `table`, `separator` выводят информацию; таблица читает массив объектов из состояния. `visible_path` и `enabled_path` задают условия из состояния. Все подписи — `{ru,en}`; стандартная тема игры, без произвольного CSS или кода.

Кнопки могут передавать `payload` для общего обработчика. Значения полей из `inputs` имеют приоритет. Ограничения: 128 узлов, глубина 8, до 24 дочерних элементов контейнера и до 64 строк видимой таблицы.

Проверка программы возвращает `program_ref`. В проекте используйте эту ссылку вместо повторной отправки исходника. Источник копируется в обычный проект для подтверждения. В памяти хранятся до 16 проверенных программ; при перезагрузке партии ссылки истекают.
