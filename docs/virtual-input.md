# Виртуальный курсор / Virtual input

Если объявленный API и наблюдаемые элементы не позволяют выполнить задачу, агент с поддержкой изображений может воспользоваться видимым курсором внутри игрового viewport. Поддерживаются наведение, клик, двойной клик, перетаскивание, прокрутка, ввод Unicode и ограниченные клавиши редактирования/навигации. Это общий механизм для интерфейсов игры и модов; готовой логики конкретного мода в нём нет.

Модель должна поддерживать изображения. Поддержка определяется автоматически для выбранного API и модели; доступны ручные «Включено» и «Выключено». [Как работает «Авто»](vision-auto.md). Доступ к `ui.pointer` и `ui.keyboard` управляется галочками в **Настройки → Харнес → Инструменты агента → Интерфейс игры**. Без разрешения инструментов нет в схеме запроса. Перед первым действием модель получает настоящий `ui.screenshot`; неудачная отправка изображения и текстовый запасной ответ не разрешают клики.

Сначала используется доступный API или наблюдаемый элемент. Для виртуального ввода агент получает снимок с временным ID, указывает координаты в пикселях этого изображения и выполняет одно действие. Масштабирование снимка в координаты viewport рассчитывается кодом. После действия автоматически прикладывается новый кадр. Старый ID повторно использовать нельзя; смена мира, модели, окна, размеров, управление игрока или другое изменяющее действие отменяют прежние координаты.

Курсор помечен «ИИ»/«AI» и подсвечивает клик. Ввод направляется через `Viewport.push_input` / `push_text_input`; системная мышь, физические кнопки и буфер обмена не используются. У поля агента сохраняется отдельная ссылка фокуса; фокус игрока возвращается после действия. Если игрок вмешивается во время действия, виртуальная кнопка освобождается, чат остаётся скрытым, а повторные попытки ввода блокируются до нового сообщения игрока. Кнопка остановки ответа также отменяет ожидающее действие. Снимки не включают рабочий стол. Разрешение использовать кадр для ввода временное; точный PNG, отправленный модели, отдельно сохраняется локально для просмотра в переписке. Лента миниатюр открывает кадр целиком на весь экран. На серии действий чат сворачивается один раз и возвращается с ответом; «Вернуться в чат» приостанавливает работу с экраном до нового сообщения, а «Остановить» отменяет ответ. Хранилище превью ограничено 256 МиБ.

Доставленное событие имеет статус `dispatched`, а не завершённую сделку или приказ. Агент проверяет новый кадр и, где доступно, состояние движка. Невозможно обещать доступ к каждой функции любого мода: скрытая логика без интерфейса остаётся недоступной. Контролы, которые опрашивают только физический `Input`, отдельные внешние окна и системные диалоги могут не реагировать на виртуальный ввод. Godot имеет общий GUI-фокус; одновременная независимая работа двух аппаратных мышей не эмулируется — приоритет всегда у игрока.

## English

A vision model can use a visible in-game cursor when a declared API and observed controls cannot perform the task. Hover, clicks, double clicks, dragging, scrolling, Unicode text and bounded editing/navigation keys are supported. This is shared infrastructure for game and mod interfaces, with no mod-specific behavior.

Image support is detected automatically per API/model; Enabled and Disabled overrides are available in Advanced settings. [How Auto works](vision-auto.md). Tool checkboxes are under **Settings → Harness → Agent tools → Game interface**. Without permission, virtual input schemas are omitted. A successful provider response to the actual game image is required before input; rejected images and text-only fallback cannot authorize clicks.

The agent first uses available APIs/observed controls. Otherwise, it receives a temporary screenshot ID and chooses one action using that image's pixel coordinates. Code maps those coordinates to the viewport. Each action automatically attaches a new rendered frame. Old frames cannot be replayed. World/model/viewport/size changes, player input and other modifying actions invalidate prior coordinates.

The cursor is labelled AI/ИИ and highlights clicks. `Viewport.push_input` / `push_text_input` route events inside the game without moving the system pointer, injecting physical button state or using the clipboard. The agent remembers its chosen field separately and restores the player's focus. Player input interrupts pending actions immediately, releases virtual buttons, leaves chat hidden and blocks further input until a new player message. Stopping the answer cancels pending input. Screenshots contain only the game viewport. Input grants expire separately from exact sent PNG previews, which remain in local player storage for transcript thumbnails and uncropped full-window viewing. During a sequence, chat hides once and returns with the answer; Return to chat pauses screen interaction until a new message; Stop cancels the answer. Preview storage is bounded at 256 MiB.

Input delivery is `dispatched`, not a completed engine transaction. Verify the new frame and authoritative state where available. Hidden functions without UI remain inaccessible. Controls polling physical `Input` exclusively, separate external windows and system dialogs may not respond. Godot shares GUI focus; this does not emulate simultaneous independent hardware mice. The player has priority.
